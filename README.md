# 온숨(ONSUM)

> 네 가지 장면 질문으로 내 방(또는 선물받을 사람)에 어울리는 향을 찾아주는, 디퓨저 브랜드 '온숨'의 반응형 웹사이트

## 1. 링크

- **Live Demo**: https://beryls1201-ux.github.io/ONSUM/
- **GitHub**: https://github.com/beryls1201-ux/ONSUM
- **Figma 와이어프레임**: https://www.figma.com/design/zFu9WgqZNCjyWiAM8oDvrc/ONSUM (사이트맵 · 와이어프레임 · 레퍼런스 · 로고)

## 2. 프로젝트 정보

- **제작 기간**: 2026.11.12 ~ 2026.11.16 (주말제외, 3일)
- **담당 역할**: 개인 프로젝트 (기여도 100%)
- **담당 범위**: 기획 문서 작성 → Figma 사이트맵·와이어프레임 → Claude Design 시안·디자인 시스템 → 바이브코딩 구현 → GitHub Pages 배포 → 요구사항 정의서(PRD)·테스트 케이스 작성

## 3. 사용 기술

- **React, Vite**: 헤더·향 카드·버튼처럼 여러 페이지에 반복되는 요소를 컴포넌트로 한 번 만들어 재사용하고, 수정 결과를 바로 확인하기 위해
- **기본 CSS**: 디자인 시스템의 색·글꼴·간격 값을 그대로 옮겨 쓰기 위해
- **GitHub Pages + GitHub Actions**: 무료 배포, main 브랜치에 push하면 자동으로 빌드·배포
- **Figma**: 사이트맵, 와이어프레임, 레퍼런스 작성 및 정리
- **Claude**: 기획 정리, Claude Design 시안·디자인 시스템, 바이브코딩(화면 구현)

## 4. 주요 기능

- **장면으로 고르는 향 찾기 테스트**: 향료 이름 대신 일상 장면 사진 카드 4문항(계절·시간대·향의 느낌)으로 답하면, 점수 규칙에 따라 12종 중 어울리는 향 1~3위를 추천
- **나를 위한 / 선물할 두 가지 모드**: 선물 모드에서는 질문이 받는 사람 기준 문장으로 바뀌고, 주문 단계에서 '선물로 보내기'가 자동으로 켜짐
- **결과 링크 공유**: 답을 주소에 담아, 링크를 연 사람도 같은 결과 화면을 볼 수 있음
- **계절 탭 향 소개 + 비회원 주문 흐름**: 봄·여름·가을·겨울 탭 → 장바구니 → 선물 옵션 → 결제 → 주문 완료 → 비회원 주문 조회까지 서버 없이 브라우저 안에서 모의 동작(localStorage)
- **선물 메시지 카드 미리보기**: 입력한 메시지(최대 100자)가 향 대표 색 띠가 들어간 카드에 실시간으로 표시, 선물 포장(+3,000원) 선택
- **브랜드 소개 스크롤 장면**: 같은 원룸 일러스트가 스크롤에 따라 아침 → 낮 → 밤으로 바뀜
- **반응형 + 움직임 줄이기 대응**: 모바일 햄버거 메뉴·1열 카드, 기기의 '움직임 줄이기' 설정 시 모든 애니메이션 생략

## 5. 트러블슈팅

### 이슈 1: 배포 주소의 하위 경로(/ONSUM/)에서 화면이 뜨지 않는 문제

- **문제**: GitHub Pages 주소가 `사용자이름.github.io/ONSUM/` 형태라, 기본 설정 그대로 빌드하면 파일 경로가 맞지 않아 흰 화면이 나옴
- **원인**: Vite의 `base` 기본값이 `/`라서 JS·CSS·이미지를 사이트 최상위 경로에서 찾음
- **해결**: `vite.config.js`에서 빌드할 때만 `base: '/ONSUM/'`로 바꾸고, React Router에도 `basename={import.meta.env.BASE_URL}`을 넣어 개발 환경과 배포 환경 모두에서 동작하게 함

### 이슈 2: 하위 페이지에서 새로고침하면 404가 나는 문제

- **문제**: `/ONSUM/cart`처럼 메인이 아닌 주소에서 새로고침하거나 결과 링크로 바로 들어오면 GitHub 404 페이지가 나옴
- **원인**: GitHub Pages는 실제 파일이 있는 주소만 보여 주는데, React Router의 페이지들은 실제 파일이 아니라 `index.html` 하나 안에서 그려짐
- **해결**: 빌드가 끝나면 `index.html`을 `404.html`로 복사하는 Vite 플러그인을 추가해, 없는 주소로 들어와도 사이트가 열리고 Router가 맞는 화면을 그리게 함

## 6. AI 활용 방식

- **맡긴 일**: 기획 문서(01~05)를 구현용 설명서(`docs/PROJECT_CONTEXT.md`)로 정리 / Claude Design으로 메인 시안과 디자인 시스템 제작 / 와이어프레임과 디자인 시스템을 React 컴포넌트로 구현 / GitHub Pages 자동 배포 설정
- **작업 방식**: `docs/PROJECT_CONTEXT.md`에 "문서에 없는 내용은 지어내지 말고, 빈 항목은 선택지와 추천안을 붙여 질문할 것", "한 단계씩 진행하고 승인 후 다음 단계로" 같은 규칙을 적어 두고, 목적 확인 → 페이지 설계 → 디자인 → 에셋 → 인터랙션 → 반응형 → 배포 7단계로 나눠 진행
- **핵심 프롬프트**: "문서에 없는 내용은 지어내지 말고, 빈 항목은 선택지와 추천안을 붙여 질문해줘. 한 단계씩 진행하고 승인받은 뒤 다음 단계로 넘어가줘."

## 7. 회고

- **배운 점**: 기획부터 시작하여 테마, 구성, 스타일, 이미지, 버튼, 문구를 기획 문서에 하나씩 완성해가며, 웹사이트를 제작했을 때, AI의 추측이 아닌 내 의도와 일치하는 웹사이트를 제작할 수 있다는 것을 알게 되었고, 바이브코딩의 활용은 기획부터 시작해야 올바르게 진행될 수 있다는 것으 배웠습니다.
- **아쉬운 점**: 결제, 비회원 주문 조회 등 다양한 서비스를 구현해 놓았지만, 실제 서버나 DB가 아닌 웹사이트 안에서만 동작하는 방식으로 작성하여 실제 사용될 페이지까지 제작해보지 못한 아쉬움을 남기게 되었습니다. 기회가 된다면 실제 서버나 DB에 사용될 웹페이지를 제작해보고 싶습니다.
